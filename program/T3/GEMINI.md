# Gemini 대화 기록 (2025년 10월 15일)

## 주요 진행 상황 및 계획

### 1. 서버 권위적 유닛 죽음 처리 시스템 완성 (2025년 10월 15일)
- **목표:** 싱글플레이 기능을 보존하면서, 네트워크 환경에서 서버 권위적으로 유닛의 죽음(데미지, 상태, 연출, 소멸)을 처리하는 안정적인 구조 확립.
- **핵심 아키텍처 (상속 및 재정의 활용):**
    - **`RobHp.cs` (부모):** 싱글플레이에서 완벽하게 동작하는 죽음 처리 로직(애니메이션, 사운드, 코루틴, `Destroy`)을 `virtual` 메소드로 구현.
    - **`RobHpNet.cs` (자식):** `RobHp`를 상속받아 네트워크 환경의 규칙을 덧씌움.
        - **`Update()` 재정의:**
            - **서버:** 유닛의 HP를 체크하여 `currentState`를 `Dead`로 변경하는 '판정'만 담당.
            - **모두(서버/클라):** 동기화된 `currentState`가 `Dead`인 것을 감지하고, 부모의 죽음 '연출' 메소드(`DeadDisposal`)를 한 번만 호출.
        - **`TakeDamage()` 재정의:** 서버만 데미지를 입도록 보호.
        - **`Destroy()` 재정의:** `Destroy(gameObject)` 대신 `Runner.Despawn(Object)`을 호출하여 오브젝트 소멸을 올바르게 동기화.
- **결과:** 역할과 책임을 명확히 분리하여, 싱글플레이와 멀티플레이 모두에서 안정적으로 동작하는 죽음 처리 시스템을 성공적으로 구현함.

### 2. 서버 권위적 유닛 동기화 (과거 기록)
- **완료:** `RobBaseNet.cs`에서 `ChangeDetector`를 사용해 유닛의 `UnitState`를 서버 -> 클라이언트로 동기화.
- **완료:** AI 로직(`RobDetector`, `RobMove`)이 서버에서만 실행되도록 상속을 이용한 `RobDetectorNet`, `RobMoveNet` 스크립트 생성. 클라이언트에서는 자동 비활성화.
- **다음 단계 (내일 작업):**
    1. 유니티 에디터에서 유닛 프리팹의 `RobDetector`, `RobMove` 컴포넌트를 `...Net` 버전으로 교체.
    2. `Network Transform` 컴포넌트를 프리팹에 추가하여 실제 움직임 동기화.
